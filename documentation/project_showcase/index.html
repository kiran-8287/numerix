1 · Opening section

What is NUMERIX?

NUMERIX is a reusable numerical-computation library written in C11. It brings multiple numerical algorithms together behind one consistent public C interface so that applications can solve, approximate, differentiate, integrate, optimize, and simulate mathematical problems without reimplementing each method.

The original academic project asked for a reusable numerical library containing common numerical methods, modular implementation, a demonstration application, error and tolerance handling, tests, examples, and documentation. NUMERIX delivers that baseline and extends it with expression-based input, piecewise functions, intelligent algorithm recommendation and selection, automatic fallback, managed execution, advanced diagnostics, and heuristic multiple-root discovery.

Numerical algorithms require careful handling of accuracy, convergence, stability, and errors. A formula can be exact on paper and unreliable on a computer: finite precision, conditioning, stopping rules, and invalid inputs all affect a computed answer. NUMERIX makes these choices visible by returning status, work information, residuals, and diagnostics alongside every result.

2 · Original requirements and how NUMERIX evolved

From a coursework assignment to an advanced library

The original C-Cubed academic assignment asked for a reusable numerical library with common numerical methods, modular implementation, a demonstration application, error/tolerance handling, tests, examples, and documentation. NUMERIX was built to satisfy that baseline and then extended through a phased redesign into a structured numerical environment.

Original baseline (coursework scope)

  • Common numerical methods across root finding, linear algebra, differentiation, interpolation, integration, optimization, and ODEs.
  • Modular C implementation with one public header.
  • A demonstration application (CLI and examples).
  • Error and tolerance handling with status codes.
  • Unit tests and test fixtures.
  • Build configuration (CMake and Make).
  • Documentation and a release contract.

NUMERIX redesign additions

  • Expression-based mathematical input (compile strings to evaluable functions).
  • Piecewise functions with boundary analysis and discontinuity classification.
  • Intelligent algorithm recommendation and automatic selection.
  • Automatic fallback and solver portfolios.
  • Managed execution: state, progress, events, step callbacks, pause/resume (Bisection).
  • Advanced numerical diagnostics: residuals, conditioning, sensitivity, convergence.
  • Heuristic multiple-root discovery with unresolved-region reporting.
  • Numerical reliability hardening, cross-compiler validation, reproducible packaging.

3 · Differentiators

What makes NUMERIX special?

NUMERIX is not merely seven categories of textbook algorithms. It wraps them in engineering systems that make numerical computation observable, selectable, and safer to use.

01

Two ways to define functions

Users can define functions as C callbacks or as mathematical expression strings. Expressions are compiled to an AST and evaluated through a callback adapter, so the same numerical routines accept both input styles.

Why useful: interactive input needs no C recompilation; callbacks give maximum flexibility for custom logic.
02

Piecewise functions

Functions with multiple segments, different expressions, open/closed boundaries, infinite bounds, boundary analysis, discontinuity classification, and one-sided limits.

Why useful: real models are often defined differently on different intervals.
03

Intelligent algorithm selection

NUMERIX analyzes a problem (bracket, derivative, piecewise boundaries) and recommends or automatically selects a suitable algorithm, with an explanation of why.

Why useful: no single method fits every problem; selection reduces developer error.
04

Automatic fallback

When an algorithm fails with a classified error, NUMERIX can attempt supported alternatives and report every attempt.

Why useful: a failed first attempt does not have to mean a failed computation.
05

Execution management

Managed executions expose state, progress, iteration/evaluation counts, timing, events, and step callbacks. Pause/resume is supported at Bisection step boundaries only.

Why useful: long computations can be observed and cooperatively controlled.
06

Numerical diagnostics

Results carry residuals, error estimates, condition and sensitivity estimates, convergence trends, and reliability classification.

Why useful: a bare result value does not tell the whole reliability story.
07

Multiple-root discovery

A bounded interval is subdivided and searched for sign-changing, tangential, endpoint, and piecewise-boundary roots, with residual verification and unresolved-region reporting.

Why useful: finding one root is not the same as finding all roots; limits are made explicit.
08

Reliability and portability

Careful error handling, numerical hardening, 35-test CMake suite, GCC/Clang validation, sanitizers, static analysis, static library, relocatable CMake package, and pkg-config metadata.

Why useful: numerical software must fail safely and build across toolchains.
4 · Architecture

One public surface, clear internal boundaries

Applications use one C API — include/numerix.h. The static library contains seven numerical modules and six supporting systems. All inputs are borrowed; outputs that NUMERIX allocates are owned by the caller until destroyed.

Figure: application and CLI link the public API; the static library implements the seven numerical modules and the supporting systems. Source paths match the repository layout.

Ownership rule.NUMERIX allocates result objects (vectors, matrices, expressions, piecewise functions, ODE solutions, execution outputs). The caller owns them and must call the matching *_destroy function. Callbacks and user_data are borrowed; NUMERIX never frees them.

Feature 1 · Verified

Mathematical expression input

Users do not always need to write a C callback function. They can provide a mathematical expression as a string, which NUMERIX compiles into an immutable, repeatedly evaluable expression object.

The internal process is:

Figure: the expression engine lexes, parses, and evaluates a string through a callback adapter that existing numerical routines can call.

Supported syntax

  • Operators: +, -, *, /, ^ (right-associative exponentiation), unary signs, parentheses.
  • Variable: x only.
  • Constants: pi, e.
  • Unary functions: sin, cos, tan, asin, acos, atan, sinh, cosh, tanh, sqrt, abs, exp, log, log10, floor, ceil.
  • Binary functions: pow, min, max.
  • Scientific notation via strtod conversion (C numeric locale).

Precedence: parentheses/functions, then exponentiation, unary signs, multiplication/division, then addition/subtraction. For example, -2^2 evaluates to -4; 2^3^2 evaluates to 512.

How a developer uses it

  1. Call numerix_expression_compile with the source string.
  2. Check the returned status; on success the caller owns the expression and must destroy it.
  3. Initialize a numerix_expression_callback_context borrowing the expression.
  4. Pass numerix_expression_callback and the context as user_data to a numerical routine.
  5. Destroy the expression after the numerical call completes.

#include "numerix.h"
#include <stdio.h>

int main(void)
{
    numerix_expression *expression = NULL;
    numerix_expression_callback_context context;
    numerix_options options;
    numerix_result result;
    numerix_error error;

    status = numerix_expression_compile("sin(x)", &expression, &error);

        return 1;

    if (status != NUMERIX_STATUS_SUCCESS) {

        numerix_expression_destroy(expression);
        return 1;
    }

    numerix_options_init(&options);
    status = numerix_integrate_adaptive_simpson(
        numerix_expression_callback, &context, 0.0,
        3.14159265358979323846, &options, 24, &result, &error);

    if (status != NUMERIX_STATUS_SUCCESS) {
        fprintf(stderr, "integration failed: %s\n", error.message);
        numerix_expression_destroy(expression);
        return 1;
    }

    printf("Integral of sin(x) 0→pi: %.10f (expected 2.0000000000)\n", result.value);
    numerix_expression_destroy(expression);
    return 0;
}

Feature 2 · Verified

C callback input

The traditional approach: the developer defines a mathematical function in C with the numerix_function signature (double f(double x, void *user_data)) and passes it to a NUMERIX routine. user_data is borrowed and lets the caller attach arbitrary context.

How a developer uses it

  1. Define double f(double x, void *user_data).
  2. Optionally define a derivative with the same signature for Newton-family methods.
  3. Configure numerix_options (tolerances, limits).
  4. Call the desired routine, passing the function pointer and user_data (often NULL).
  5. Check numerix_status, then read numerix_result.

Feature 4 · Verified

Piecewise mathematical functions

A single continuous expression is insufficient for problems defined differently on different intervals. NUMERIX represents piecewise functions as ordered, non-overlapping segments, each with an expression, lower/upper bounds, and open/closed inclusion flags.

For example:

f(x) = ⎧ x²,        x < 0
⎨ sin(x),   0 ≤ x < 2
⎩ x + 1,     x ≥ 2

Figure: segments and boundaries on a number line; boundaries at 0 and 2 are shown as transition points.

What NUMERIX supports

  • Segment expressions (strings compiled at add time, owned by the piecewise object).
  • Lower and upper boundaries, including infinite bounds (-INFINITY, INFINITY).
  • Open/closed inclusion flags per boundary.
  • Boundary analysis: left/right limits, function value, discontinuity type (continuous, jump, removable, infinite, unknown), numeric confidence.
  • One-sided limits, gap detection, overlap detection, continuity/discontinuity classification.
  • Boundary-aware integration (splits at known segment boundaries; rejects gaps) and boundary-guarded differentiation.

C · piecewise function
#include "numerix.h"
#include <math.h>
#include <stdio.h>

int main(void)
{
    numerix_piecewise_function *function = NULL;
    numerix_piecewise_boundary_report report;
    numerix_result result;
    numerix_error error;
    numerix_status status;
    double value;

    status = numerix_piecewise_create(&function, &error);
    if (status != NUMERIX_STATUS_SUCCESS) {
        fprintf(stderr, "create failed: %s\n", error.message);
        return 1;
    }

    status = numerix_piecewise_add_expression(
        function, -INFINITY, 0.0, 0, 0, "x^2", &error);
    if (status == NUMERIX_STATUS_SUCCESS) {
        status = numerix_piecewise_add_expression(
            function, 0.0, INFINITY, 1, 0, "2*x", &error);
    }
    if (status != NUMERIX_STATUS_SUCCESS) {
        fprintf(stderr, "add segment failed: %s\n", error.message);
        numerix_piecewise_destroy(function);
        return 1;
    }

    status = numerix_piecewise_evaluate(function, -2.0, &value, &error);
    if (status == NUMERIX_STATUS_SUCCESS) printf("f(-2) = %.6f\n", value);
    status = numerix_piecewise_evaluate(function, 0.0, &value, &error);
    if (status == NUMERIX_STATUS_SUCCESS) printf("f(0) = %.6f\n", value);

    status = numerix_piecewise_analyze_boundary(function, 0.0, NULL, &report, &error);
    if (status == NUMERIX_STATUS_SUCCESS) {
        printf("Boundary x=0: type=%d confidence=%d\n",
               (int)report.type, (int)report.confidence);
    }

    status = numerix_piecewise_integrate_trapezoid(
        function, -2.0, 2.0, 100, NULL, &result, &error);
    if (status == NUMERIX_STATUS_SUCCESS) {
        printf("Integral on [-2, 2] = %.8f\n", result.value);
    }

    numerix_piecewise_destroy(function);
    return 0;
}

Feature 5 · Verified

Intelligent algorithm recommendation

One numerical algorithm is not ideal for every problem. NUMERIX can analyze a user's problem and recommend a suitable algorithm, with reasons and limitations.

Figure: the recommendation flow considers bracket, derivative availability, and piecewise boundaries, then produces a recommended algorithm plus reason and limitation strings.

Information considered

The implementation considers the problem category, representation (callback/expression/piecewise), bracket availability, initial estimates, derivative availability, whether the derivative appears zero or non-finite, piecewise boundary crossings, probe evaluations, and historical diagnostics. It produces a recommended algorithm, a suitability level (UNAVAILABLE / CONDITIONAL / SUITABLE), up to four alternatives, and reason/limitation strings.

#include "numerix.h"
#include <math.h>
#include <stdio.h>
#include <string.h>

static double quadratic(double x, void *data)
{
    (void)data;
    return x * x - 2.0;
}

{
    (void)data;
    return 2.0 * x;
}

int main(void)
{
    numerix_recommendation_request request;
    numerix_recommendation recommendation;
    numerix_error error;
    numerix_status status;

    memset(&request, 0, sizeof(request));
    request.category = NUMERIX_PROBLEM_ROOT_FINDING;
    request.representation = NUMERIX_REPRESENTATION_CALLBACK;
    request.function = quadratic;
    request.derivative = quadratic_derivative;
    request.problem.root.lower = 0.0;
    request.problem.root.upper = 2.0;
    request.problem.root.initial = 1.0;
    request.problem.root.has_bracket = 1;
    request.problem.root.has_initial = 1;

    status = numerix_recommend_algorithm(&request, &recommendation, &error);
    if (status != NUMERIX_STATUS_SUCCESS) {
        fprintf(stderr, "recommendation failed: %s\n", error.message);
        return 1;
    }

    printf("Recommended: %s\n",

    printf("Reason: %s\n", recommendation.reason[0]);
    printf("Limitation: %s\n", recommendation.limitation[0]);
    printf("Suitability: %d\n", (int)recommendation.suitability);
    return 0;
}

Feature 6 · Verified

Automatic algorithm selection and execution

NUMERIX distinguishes three modes: (1) asking for a recommendation only, (2) asking NUMERIX to select and execute automatically, and (3) explicitly choosing a method manually. Direct method APIs remain available to developers who want full control.

Figure: automatic selection analyzes, picks, runs, and returns the result plus execution information.

Real APIs

  • numerix_root_solve_auto — automatic selection and execution with fallback options.
  • numerix_root_solve_portfolio — runs multiple methods sequentially and reports the best.
  • Direct methods (numerix_root_bisection, numerix_root_brent, etc.) — manual selection.

Verified output
C · automatic selection with fallback
#include "numerix.h"
#include <math.h>
#include <stdio.h>
#include <string.h>

static double f(double x, void *d) { (void)d; return (x - 1.0) * (x - 1.0) * (x - 1.0) + 0.5; }
static double df(double x, void *d) { (void)d; return 3.0 * (x - 1.0) * (x - 1.0); }

int main(void)
{
    numerix_recommendation_request request;
    numerix_root_selection_options selection;
    numerix_root_selection_report report;
    numerix_result result;
    numerix_error error;
    numerix_status status;

    memset(&request, 0, sizeof(request));
    request.category = NUMERIX_PROBLEM_ROOT_FINDING;
    request.representation = NUMERIX_REPRESENTATION_CALLBACK;
    request.function = f;
    request.derivative = df;
    request.problem.root.lower = 0.0;
    request.problem.root.upper = 2.0;
    request.problem.root.initial = 1.0;
    request.problem.root.has_bracket = 1;
    request.problem.root.has_initial = 1;

    selection.mode = NUMERIX_SELECTION_EXPLICIT;
    selection.explicit_algorithm = NUMERIX_ALGORITHM_NEWTON;
    selection.enable_fallback = 1;

    status = numerix_root_solve_auto(&request, &selection, &result, &report, &error);
    if (status == NUMERIX_STATUS_SUCCESS) {
        printf("Fallback used after %s; final method %s found %.12f\n",
               numerix_algorithm_name(report.initially_selected),
               numerix_algorithm_name(report.final_algorithm),
               result.value);
    } else {
        fprintf(stderr, "auto solve failed: %s\n", error.message);
        return 1;
    }
    return 0;
}

Feature 7 · Verified

Failure classification and automatic fallback

Numerical algorithms can fail: invalid initial interval, missing/too-small derivative, divergence, stagnation, iteration limit, overflow, domain error. NUMERIX classifies supported failures and, when enabled, attempts supported alternatives.

Each attempt is recorded in numerix_algorithm_attempt with algorithm, status, reason, error, and result. The numerix_root_selection_report records the original failure, whether fallback was used, the final algorithm, and attempt count.

Figure: one algorithm fails and a supported alternative is attempted.

Limitation.Fallback is not universal. It applies to classified failures with supported alternatives. Some failures (allocation failure, singular matrix, unrecoverable divergence) do not trigger fallback. The report records every attempt so the developer can see what was tried.

Multiple-root discovery

numerix_root_find_all searches a bounded interval for multiple roots. It subdivides the interval, detects sign changes, checks tangential-root candidates, checks endpoints, refines candidates, verifies residuals, merges nearby roots, estimates multiplicity heuristically, and reports unresolved regions.

Figure: several roots including a tangential one (touching the axis without crossing), plus an unresolved region where the search could not conclude.

What the search reports

  • Discovered roots with value, residual, refinement algorithm, verification level.
  • Root kind: sign-changing, tangential, sampled-zero, endpoint, piecewise-boundary, repeated.
  • Heuristic multiplicity estimate (never an exact proof).
  • Unresolved intervals with reasons.
  • Evaluation counts, subdivisions, elapsed time.

Feature 14 · Verified

Forward error, backward error, and conditioning

Forward error: how far the computed answer is from the correct/reference answer. Backward error: how much the original input must change for the computed answer to be exact. Conditioning: how sensitive the problem is to small input changes.

Conditioning is a property of the mathematical problem; stability is a property of the algorithm. A well-conditioned problem solved by an unstable algorithm can still be inaccurate; an ill-conditioned problem can have large forward error despite a tiny residual.

C: forward error + root condition

#include "numerix.h"
#include <stdio.h>

{

    numerix_root_condition_report cond;
    numerix_error error;
    numerix_status status;

    status = numerix_diagnostics_forward_error_scalar(1.41421356237, 1.4142135623730951,
                                                      &ferr, &error);
    if (status != NUMERIX_STATUS_SUCCESS) {
        fprintf(stderr, "forward error failed: %s\n", error.message);
        return 1;
    }
    printf("Forward absolute error: %.3e\n", ferr.absolute_error);
    if (ferr.has_relative_error)
        printf("Forward relative error: %.3e\n", ferr.relative_error);

        NULL, NULL, NULL, 1.41421356237, 1e-6, NULL,
        &cond, &error);

        fprintf(stderr, "root condition failed: %s\n", error.message);
        return 1;

    return 0;

    printf("]\n");

    numerix_vector_destroy(x);
    numerix_vector_destroy(b);
    numerix_matrix_destroy(a);
    return 0;

#include "numerix.h"
#include <math.h>
#include <stdio.h>
#include <string.h>

static numerix_status oscillator(double x, const double *y, size_t dim,
                                  double *dydx, void *ud)
{
    (void)x; (void)ud;
    if (dim < 2) return NUMERIX_STATUS_INVALID_DIMENSIONS;
    dydx[0] = y[1];
    dydx[1] = -y[0];
    return NUMERIX_STATUS_SUCCESS;
}

int main(void)
{
    numerix_ode_solution solution;
    numerix_error error;
    numerix_status status;
    double y0[2] = {1.0, 0.0};
    size_t i;

    memset(&solution, 0, sizeof(solution));
    status = numerix_ode_rk4(oscillator, NULL, 0.0, y0, 2, 0.1, 63, &solution, &error);
    if (status != NUMERIX_STATUS_SUCCESS) {
        fprintf(stderr, "RK4 failed: %s\n", error.message);
        return 1;
    }
    printf("final x = %.6f\n", solution.x[solution.points - 1]);
    printf("final y = [%.6f, %.6f]\n",
           solution.y[2 * (solution.points - 1)],
           solution.y[2 * (solution.points - 1) + 1]);
    printf("function evaluations: %zu\n", solution.function_evaluations);
    numerix_ode_solution_destroy(&solution);
    return 0;
}

Using the installed library (CMake consumer)

CMake
find_package(NUMERIX 0.2 CONFIG REQUIRED)
add_executable(my_program main.c)
target_link_libraries(my_program PRIVATE NUMERIX::numerix)

Configure with -DCMAKE_PREFIX_PATH=/path/to/numerix. The installed target is NUMERIX::numerix; POSIX math linkage (-lm) propagates through the imported target. pkg-config: pkg-config --cflags --libs --static numerix.

Honesty note.Shared-library builds are explicitly rejected. Native Windows/MSVC/macOS builds are configured but not yet tested in this work.
9 · Testing & verification

How NUMERIX is tested

See Feature 19 for the test table. Tests run via CTest from the build directory. The default suite has 35 tests; 36 with the optional benchmark-raw-verification test. Installed C and C++ consumers pass 2/2 in each GCC/Clang configuration.

10 · Conclusion
N∑

A numerical library is more than its fastest method.

NUMERIX is a reusable C11 numerical-computation library with seven numerical modules, multiple algorithms per module, callback and expression-based function input, piecewise functions, intelligent recommendation and execution, managed execution with monitoring, advanced diagnostics, heuristic multiple-root discovery, and numerical reliability hardening.

It attempts to provide a structured environment for defining, selecting, executing, monitoring, and analyzing numerical computations — not merely implementing numerical formulas.
